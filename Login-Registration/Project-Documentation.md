# Login and Registration Functional Testing

## 1. Project Overview

This project focuses on performing manual functional testing of the Login and Registration modules of a web application.

The main objective is to verify that users can register accounts, log in using valid credentials, receive appropriate validation messages for invalid inputs, and log out successfully.

## 2. Project Objectives

* Understand the functionality of Login and Registration modules.
* Identify positive and negative test scenarios.
* Design and execute manual test cases.
* Validate mandatory fields and input validation.
* Identify and document application defects.
* Prepare a test execution report.
* Understand the practical software testing process.

## 3. Application Under Test

**Application:** Automation Exercise
**Website:** https://automationexercise.com/
**Testing Type:** Manual Functional Testing
**Testing Approach:** Black-box Testing
**Testing Method:** Positive and Negative Testing

## 4. Scope of Testing

### Login Module

* Login with valid credentials.
* Login with invalid credentials.
* Login with empty fields.
* Login using an unregistered email.
* Email input validation.
* Logout functionality.

### Registration Module

* Registration using valid details.
* Registration using an existing email.
* Mandatory field validation.
* Email format validation.
* Personal information field validation.
* Account creation confirmation.
* Login after successful registration.

## 8. Test Execution Process

1. Open the application.
2. Navigate to the Login or Registration module.
3. Review the test scenario.
4. Execute the corresponding test case.
5. Enter the required test data.
6. Compare the actual result with the expected result.
7. Mark the test case as Pass, Fail, Blocked or Not Applicable.
8. Document any defects found.
9. Update the execution summary.

## 9. Defect Reporting Process

When an actual defect is identified:

1. Record the related test case ID.
2. Write a clear defect title.
3. Provide reproducible steps.
4. Mention the expected result.
5. Mention the actual result.
6. Assign severity and priority.
7. Track the defect status.

Only defects observed during actual testing should be reported.

The project helps build a foundation in manual software testing and real-world QA documentation.
